AGENTS.md를 먼저 읽고 준수해줘.

이번 작업은 기존 기능 안정화 + OSS 전환 작업이다.
기존 정상 기능을 깨뜨리지 말고 기능별로 영향 범위를 확인한 뒤 최소 수정해줘.

[최우선 원칙]

1. 먼저 현재 기능 전체를 조사해서 OSS로 대체 가능한 부분을 확인.
2. 유지보수 중이고 라이선스가 적절하며 현재 non-React 구조와 호환되는 OSS가 있으면 custom 구현 대신 OSS 사용.
3. 동일 기능의 OSS + custom 중복 구현 금지.
4. 버튼, 팝업/modal, 아이콘, tooltip, dialog, dropdown, drag/drop, formatter/parser, 네트워크 요청, editor extension 등 UI/스크립트 영역도 OSS 대체 가능 여부 확인.
5. 기존에 이미 설치된 OSS가 있으면 새 라이브러리 추가보다 기존 OSS 우선.
6. 적절한 OSS가 없는 기능은 새 복잡한 custom 로직을 만들지 말고 삭제/비활성화.
7. 예외:
   - Gemini API 맞춤법 교정
   - 현재 필요한 BookProject application state 연결
   - XHTML 자동수정 custom 로직
8. OSS를 넣기 위해 EPUB 데이터 보존을 깨뜨리면 안 됨.
9. unrelated refactor / 전체 파일 rewrite / 전체 formatter 금지.
10. 공통 함수 수정 전 모든 호출처 확인.

먼저 짧게 기능별로:
기능 / 현재 구현 / OSS 후보 / 실제 OSS 사용 여부 / 조치
를 확인하고 바로 작업해줘.


================================
1. 상태 구조
================================

canonical state:

BookProject.selectedChapterId
BookProject.chapters[].xhtml

chapter identity는 index가 아니라 chapter.id 기준.

책의 구성 / Monaco / Tiptap / Preview는 항상 같은 selectedChapterId를 표시.

저장, 임시저장, 삭제, 추가, mode 전환 후에도 서로 다른 장을 보여주면 안 됨.


==================================================
2. XHTML 저장 버그 — 최우선
==================================================

현재 Monaco에서 XHTML을 수정하고 저장해도
mode/chapter 전환 또는 reload 후 이전 내용으로 돌아가는 문제가 있음.

정상 저장 흐름:

Monaco latest value
→ XHTML validation
→ selectedChapterId의 chapter.xhtml 업데이트
→ BookProject 확정
→ Dexie 저장
→ 필요 시 server 저장

반드시 확인:
- Monaco 최신값을 실제로 저장하는지
- chapters[0], selectedIndex, stale snapshot 사용 여부
- Tiptap/restore/save callback이 이전 값을 다시 덮는지

validation은 우회하지 말 것.

실제 XHTML 오류가 있으면 line / column / parser error를 확인 가능하게 해줘.


==================================================
3. 임시저장 데이터 오염 — 최우선
==================================================

현재 임시저장 후 첫 번째 장 내용이 다른 장에도 복제되는 문제가 있음.

원칙:

현재 active editor
→ selectedChapterId
→ 해당 chapter 하나만 업데이트
→ 전체 BookProject snapshot 저장

current editor content를 모든 chapter.xhtml에 쓰면 안 됨.

chapters[0], firstChapter, map/forEach, selectedIndex,
Dexie snapshot/restore, Tiptap setContent 경로를 조사해줘.


==================================================
4. XHTML 자동수정
==================================================

기존 버튼/custom 로직 유지.
HTML 정규화는 사용하지 말고 XHTML 기준으로만 처리.

버튼 한 번 클릭 시 모든 chapter.xhtml에 독립적으로 적용:

<br> → <br />
<hr> → <hr />
<img ...> → <img ... />
<meta ...> → <meta ... />
<link ...> → <link ... />
<input ...> → <input ... />

조건:
- 한 장 내용을 다른 장에 복사 금지
- 정상 XHTML 유지
- <br//> 금지
- attribute/text/href/src/id/class/epub:type/xml:lang 보존
- 전체 formatter 재작성 금지

자동수정 결과가 XML/XHTML parser에서 실제 유효한지 검사.

자동수정 후:
- BookProject 모든 수정 장 반영
- 현재 장 Monaco 즉시 반영
- dirty state 갱신

가능하면:
"총 N개 장 / M개 항목 수정"
표시.



==================================================
5. Monaco ↔ Tiptap ↔ Preview 양방향 포커싱
==================================================

세 영역 모두 양방향:

Monaco 클릭/커서 이동
→ Tiptap + Preview 같은 위치

Tiptap 클릭/caret 이동
→ Monaco + Preview 같은 위치

Preview 텍스트/이미지/element 클릭
→ Monaco + Tiptap 같은 위치

가능하면 custom 문자열 검색 대신
안정적인 OSS/source mapping 방식이 있는지 먼저 조사.

매핑 우선순위:
direct mapping
→ element
→ innerText
→ text child
→ 인접 content
→ 기존 scroll 유지

주의:
- 동일 문장 여러 개 구분
- <br />, <hr />, <img /> 지원
- 새 입력 시 Preview bottom jump 금지
- mapping 실패 시 맨 아래 이동 금지
- chapter 변경 시 이전 mapping 폐기
- programmatic 이동 feedback loop 방지

6. 표지 구조 변경
==================================================

기존 별도 "표지 이미지" 버튼/영역 삭제.

새 프로젝트 생성 시 기본 구조:

1. 표지
2. 각주 페이지

표지는 항상 첫 번째 기본 항목.

표지 선택 시:
- 일반편집 → 실제 표지 이미지
- Preview → 실제 표지 이미지
- XHTML → cover XHTML이 있으면 표시, 아니면 read-only

일반 chapter에는 표지 전용 DOM을 렌더하지 말 것.

본문 <img> 표시는 그대로 유지.

저장 후 일반편집에만 첫 장 phantom content가 나타나는
default/fallback/chapters[0]/setContent(firstChapter) 로직을 찾아 제거.

BookProject에 없는 내용이 Tiptap에만 존재하면 안 됨.

7. 삭제 기능
==================================================

기존 삭제 버튼 하나로 처리.

선택 대상이:

일반 chapter
→ 해당 chapter 삭제

표지
→ cover 관련 데이터만 삭제

각주 페이지
→ 해당 각주 페이지 삭제

index 기준 삭제 금지.
selected item type/id 기준.

표지 삭제 시 다음 장/첫 본문 삭제 금지.
각주 삭제 시 다른 chapter 삭제 금지.

삭제 후 selectedChapterId를 유효한 장으로 갱신하고
Monaco/Tiptap/Preview 모두 같은 장 표시.

8. 각주 자동 동기화
==================================================

기본 "각주 페이지"는 중앙 footnote page.

본문에서 각주 추가 시:
- 본문 noteref 번호 생성
- 각주 페이지에 동일 번호/내용 자동 생성
- id/href 양방향 연결

EPUB 3 semantic 구조 사용 가능하면 우선:

epub:type="noteref"
epub:type="footnote"

본문:
각주 번호 클릭
→ 각주 페이지 해당 각주로 이동

각주 페이지:
각주 번호/back link 클릭
→ 원래 chapter의 정확한 참조 위치로 복귀

각주 추가/수정/삭제 시:
번호 / id / href / 내용 함께 동기화.

여러 chapter 각주를 지원하고
chapter index가 아니라 chapter.id/originalPath/실제 XHTML path 기준으로 링크 생성.

chapter 삭제 시 해당 chapter 각주만 제거.

DnD 후에도 링크 유지.

각주 페이지를 사용자가 삭제한 상태에서 새 각주를 추가하면
일관된 정책으로 자동 재생성해줘.

12. XHTML 편집모드 기본 포맷
==================================================

XHTML 편집모드에 진입하거나 chapter를 열 때
기본 표시 상태를 Monaco의 "Format Document"가 적용된 상태로 보여줘.

즉 사용자가 별도로 Format Document를 실행하지 않아도
XHTML 편집모드에서는 처음부터 가독성 좋게 정리된 형태로 표시.

조건:
- 가능하면 Monaco의 기본/등록된 document formatting provider 사용
- custom regex formatter 새로 만들지 말 것
- canonical XHTML 의미 변경 금지
- text / attribute / href / src / id / class / epub:type / xml:lang 보존
- <br />, <hr />, <img ... /> 등 XHTML self-closing 문법 유지
- inline 요소를 과도하게 분리하지 말 것
- Format Document 때문에 저장 데이터가 의도치 않게 변형되지 않게 할 것

중요:
단순히 "보기만 포맷"할 수 있다면 display/editor formatting과 canonical source를 분리하는 방식을 우선 검토.
만약 Monaco Format Document가 실제 model value를 변경하는 구조라면,
변경된 XHTML이 유효한지 검증하고 BookProject와 동일한 값으로 동기화.

chapter 전환 시에도 해당 chapter의 최신 XHTML 기준으로 Format Document 적용.

테스트:
- XHTML 편집모드 최초 진입 시 자동 formatting
- 다른 chapter 이동 후에도 자동 formatting
- save → reload 후 XHTML 의미/링크/attribute 유지
- <br />, <img ... /> 등이 HTML식으로 깨지지 않음
- formatting 때문에 사용자 텍스트가 변경되지 않음
